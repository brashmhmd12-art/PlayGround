# التدفقات ودورات الحياة (Flows & Lifecycles)

## 1. تدفق المصادقة (Authentication Flow)

```
طالب/مشرف -> إدخال بيانات -> الخادم:
  1. فحص Rate Limit + حالة القفل (Brute Force: تأخير تصاعدي + قفل مؤقت)
  2. مقارنة bcrypt (زمن ثابت)
  3. للمشرف: طلب رمز 2FA (TOTP) إذا مفعّل
  4. إصدار جلسة: HttpOnly + Secure + SameSite=Lax، تدوير عند كل دخول
  5. تسجيل محاولة الدخول (ناجحة/فاشلة) + الجهاز في audit_logs
  - تسجيل الخروج من جميع الأجهزة: إبطال كل الجلسات ما عدا الحالية (خيار)
```

## 2. تدفق المشرف (Admin Flow)

```
دخول -> لوحة المؤشرات (طلاب، امتحانات، نشطة، منتهية، بانتظار تصحيح،
نتائج منشورة، آخر الأنشطة، إشعارات الإدارة)
  -> إدارة الطلاب: إضافة/تعديل/تعطيل/حذف ناعم/إعادة تعيين كلمة مرور/بحث
  -> إنشاء امتحان -> إضافة أسئلة (يدوي/من البنك/عشوائي) -> مراجعة -> نشر/جدولة
  -> قائمة التصحيح -> تصحيح يدوي سؤالا سؤالا -> اعتماد -> نشر النتائج
  -> النتائج والإحصاءات (متوسط، أعلى، أدنى، ناجحون/راسبون، رسوم)
  -> سجل التدقيق + النسخ الاحتياطي
```

## 3. تدفق الطالب (Student Flow)

```
دخول -> لوحة الطالب (متاحة/قادمة/بدأها/مكتملة/نتائج/إشعارات بعداد غير المقروء)
  -> تفاصيل امتحان (المدة، العلامة، المحاولات المتبقية، رمز الدخول إن وجد)
  -> بدء -> واجهة الامتحان (عداد، خريطة أسئلة، حفظ تلقائي)
  -> تأكيد التسليم -> إيصال استلام
  -> نتيجة (فورية إن سمح الإعداد ولا يوجد يدوي، وإلا: قيد التصحيح + إشعار لاحق)
  -> مراجعة الإجابات (فقط إن سمح الإعداد)
```

## 4. دورة حياة الامتحان (Exam Lifecycle)

```
DRAFT -> SCHEDULED -> PUBLISHED -> ACTIVE -> EXPIRED -> ARCHIVED
```

| الحالة | يراها الطالب؟ | يمكن التقديم؟ |
|---|---|---|
| draft | لا | لا |
| scheduled | نعم (قادم، بدون زر بدء) | لا |
| published | نعم | فقط داخل النافذة |
| active | نعم | نعم |
| expired | نعم (كمكتمل/منتهي) | لا |
| archived | لا | لا |

قواعد: الانتقال الزمني تلقائي عبر مهمة مجدولة (لا يعتمد على طلب طالب).
تعديل الأسئلة بعد النشر: مسموح للمشرف لكنه ينشئ نسخة جديدة ولا يمس لقطات
المحاولات السابقة (Versioning).

## 5. دورة حياة المحاولة (محور منع الغش الزمني)

```
بدء (ساعة الخادم تسجل started_at + server_deadline)
 -> حفظ تلقائي كل بضع ثوانٍ (مع seq)
 -> انقطاع إنترنت: رسالة عدم استقرار + طابور محلي + مزامنة بـ seq عند العودة
 -> تحديث/إغلاق المتصفح: إعادة فتح تستأنف من نفس server_deadline (لا وقت إضافي)
 -> انتهاء الوقت: الخادم يرفض أي حفظ بعد deadline ويسلم تلقائيا
 -> تسليم مزدوج: مفتاح عدم التكرار يجعله عملية واحدة
```

## 6. دورة حياة التصحيح (Grading Lifecycle)

```
تسليم -> تصحيح تلقائي فوري (موضوعي) داخل المعاملة
  -> إن وجدت أسئلة تحريرية: الحالة grading + مهمة في قائمة المصحح
  -> المصحح يفتح إجابة الطالب + العلامة القصوى + حقل الدرجة + ملاحظات
  -> حفظ لكل سؤال -> اكتمال الكل -> final = auto + manual
  -> نشر النتيجة (يدوي/تلقائي حسب الإعداد) -> إشعار الطالب
  -> أي تعديل لاحق على درجة: سجل في grade_history + audit
```

## 7. دورة حياة الإشعارات (Notification Lifecycle)

```
حدث (نشر نتيجة، اكتمال تصحيح، امتحان جديد، تذكير قبل البدء بساعة عبر مهمة مجدولة)
 -> إدراج في notifications + عداد غير المقروء
 -> الطالب يفتح -> تعليم كمقروء (فردي/الكل)
أنواع الطالب: نتيجة منشورة، اكتمال تصحيح، امتحان جديد، تذكير.
أنواع الإدارة: تقديم جديد يحتاج تصحيح، محاولات دخول فاشلة متكررة، أخطاء نظام.
```

## 8. حالات الواجهة المطلوبة (لا صفحة صامتة أبدا)

تحميل (Loading/Skeleton)، فارغ (Empty)، خطأ (Error مع إعادة المحاولة)،
نجاح (Success)، تأكيد (Confirmation dialogs)، تنبيهات فورية (Toast).
كل عملية مهمة تعطي Feedback صريحا.
