# نموذج التهديدات (Threat Model)

## 1. الأصول المطلوب حمايتها

1. الإجابات النموذجية (أعلى حساسية).
2. إجابات الطلاب ونتائجهم (خصوصية + نزاهة).
3. حساب المشرف وصلاحياته.
4. سلامة الوقت والدرجات (نزاهة الامتحان).
5. سجل التدقيق (قابلية المحاسبة).

## 2. الجهات الفاعلة

- طالب فضولي: أدوات المطور، تحديث الصفحة، تجربة روابط.
- طالب متعمد: سكربتات، طلبات مزورة، مشاركة حساب.
- دخيل خارجي: تخمين كلمات المرور، حقن، تزوير طلبات.
- مشرف (خطر داخلي منخفض لكن موجود): أخطاء تعديل — تعالج بالسجلات والنسخ.

## 3. التهديدات والتخفيفات (بصدق، بدون ادعاء منع مطلق)

| التهديد | التخفيف | الخطر المتبقي |
|---|---|---|
| طالب يفتح لوحة الإدارة بالرابط | فحص الدور في الخادم على كل طلب (RBAC)، لا يوجد أي مسار إداري يقبله دور طالب | لا شيء إذا طُبق الفحص في كل طبقة |
| تعديل النتيجة/العلامة من DevTools | الخادم يتجاهل أي حقل درجة/دور/مدة من العميل ويعيد الحساب | لا شيء (الحساب خادمي بالكامل) |
| قراءة الإجابة الصحيحة من الشبكة | الإجابات النموذجية لا تُرسل للطالب أبدا؛ المراجعة تعرض بعد النشر فقط وبدون المفاتيح الخام | تسرب عبر مراجعة مسموحة — يُضبط بالإعدادات |
| تسليم مزدوج / سباق | مفتاح عدم تكرار + قيد فريد + معاملة | لا شيء |
| انتهاء الوقت والتلاعب بساعة الجهاز | ساعة الخادم + deadline ثابت + رفض الحفظ المتأخر | طالب يتعمد عدم التسليم: يُسلم تلقائيا بمنتصف الليل؟ لا — يُسلم فور deadline |
| تحديث/إغلاق/جهاز آخر | استئناف بنفس deadline؛ جلسة واحدة نشطة للامتحان (فتح ثانٍ = استئناف لا محاولة جديدة) | لا وقت إضافي ممكن |
| Brute Force على الدخول | حد معدل + تأخير تصاعدي + قفل مؤقت + تنبيه المشرف + سجل | هجوم موزع بطيء — يُرصد بالسجلات والتنبيهات |
| SQL Injection | استعلامات مُعاملَة (ORM/Prepared) حصرا، لا تركيب نصي أبدا | لا شيء مع الالتزام الصارم |
| XSS | ترميز المخرجات + سياسة CSP + تعقيم مدخلات HTML (الأسئلة/الإجابات) | محتوى معروض من مشرف — يُعقم أيضا (لا ثقة عمياء بالداخل) |
| CSRF | جلسات SameSite=Lax + رمز CSRF للعمليات المغيرة، أو JWT في الذاكرة مع Origin check | يُختبر صراحة قبل الإطلاق |
| تصعيد صلاحيات (طالب -> مشرف) | الدور يُقرأ من الجلسة الخادمية فقط، لا من أي حقل عميل | لا شيء |
| تعديل سؤال بعد بدء الامتحان | النسخ/اللقطات: المحاولات القائمة محصنة | لا تأثير رجعي ممكن |
| الوصول لنتيجة طالب آخر | فحص الملكية (student_id من الجلسة) على كل طلب نتيجة | لا شيء |
| فقدان البيانات (حذف بالخطأ) | حذف ناعم + نسخ احتياطي يومي + استعادة مُختبرة | نافذة فقدان قصوى = منذ آخر نسخة (تُذكر بصراحة) |

## 4. ما لا ندعيه (التزام قسم 37)

- لا ندعي "غير قابل للاختراق" أو "منع الغش 100%".
- إجراءات تقليل الغش (تعطيل النسخ، تنبيه مغادرة الصفحة، عشوائية الترتيب،
  نسخ مختلفة، بنك عشوائي) وسائل ردع وتسجيل، لا ضمانات. المراقبة البشرية
  (مراقب قاعة/كاميرا) خارج نطاق البرمجيات ونذكر ذلك صراحة.
- JavaScript وحده ليس حماية: كل قيد واجهي (منع نسخ/اختصارات) يقابله قيد
  خادمي حقيقي (زمن، ملكية، حالة).

## 5. متطلبات قابلة للتدقيق

- سجل تدقيق إلحاقي لا يمكن تعديله عبر API.
- تصدير السجلات والنتائج (Excel/PDF) لاحقا للمراجعة الخارجية.
- مراجعة أمنية قبل كل إطلاق (قائمة الفحص في وثيقة المراجعات).
